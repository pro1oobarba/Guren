# Roadmap

Бэклог полировки ядра, по приоритету. P0 — реальные дыры в надёжности,
не украшательства. Ниже — фичи и операционка, по убыванию важности.
См. [GOALS.md](GOALS.md) для контекста "зачем" и принципов, которым
бэклог не должен противоречить.

## P0 — надёжность

Все четыре пункта закрыты 2026-08-05, детали и обоснование — в
[CHANGELOG.md](CHANGELOG.md).

- [x] Таймаут на `chat()` в реальных запросах (`Router.execute()`,
      45с по умолчанию, настраивается через `generate({ timeoutMs })`).
- [x] Обрезка истории памяти (`MemoryManager`: `maxStoredMessages` на
      диске, `maxContextChars` в реальный запрос модели).
- [x] Линтер `.env` (`npm run doctor`, `scripts/checkEnv.js`) — ловит
      все три бага, что находились вручную за сессию.
- [x] Базовые автотесты (`npm test`, `node:test`, 14 тестов, без
      зависимостей) — `ModelRegistry`, `Router.rank/execute`, `MemoryManager`.

## P1 — архитектурная полировка

Все четыре пункта закрыты 2026-08-05, детали — в [CHANGELOG.md](CHANGELOG.md).

- [x] `AI.status()` — программный снимок реестра (`state`: alive/cooldown/
      retryable, tier, latency, error) без парсинга консольных логов.
- [x] Рандомизация внутри одного tier (джиттер в `Router.rank()`,
      инъекция `random` для детерминированных тестов).
- [x] Файловое логирование (`LOG_FILE=./kernel.log` в `.env`, опционально,
      без ANSI, полный ISO-таймстамп; по умолчанию не меняет поведение).
- [x] JSDoc-типы на публичном API (`kernel.js`: `GenerateArgs`,
      `GenerateResult`, `ModelStatus` и т.д.).

## P2 — новые возможности

## P3 — операционка и безопасность

Все три пункта закрыты 2026-08-05, детали — в [CHANGELOG.md](CHANGELOG.md).

## Внешняя интеграция (2026-08-06) — driven by ai-dungeon-master

Первый реальный внешний потребитель ядра вскрыл 3 пробела, все закрыты
в день обнаружения — детали в [CHANGELOG.md](CHANGELOG.md).

- [x] `responseFormat`/`maxTokens` passthrough — нужен для честного
      JSON-режима у DM-ответов и контроля бюджета токенов у
      reasoning-моделей, которые обрывались до финального ответа.
- [x] `stickyMessages` в `MemoryManager` ("амнезия ДМ") — длинная сессия
      вытесняла завязку кампании из контекста. Дефолт 2 (первая пара
      user+assistant).

Ещё 3 пункта из внешнего ревью (не от Claude) остаются открытыми,
не форсировали их только потому, что не блокируют текущую интеграцию:
- Синхронная запись `MemoryManager`/`UsageTracker` (`fs.writeFileSync`)
  блокирует event loop — станет проблемой при параллельных запросах в
  одном процессе (сейчас у `ai-dungeon-master` трафик не такой).
- `AI.init()` всегда гоняет полный health-check при старте процесса
  (до минуты) — нет кэша `health-report.json` между рестартами.
- Кулдаун при 429 классифицируется по тексту ошибки, не по заголовку
  `Retry-After`, который провайдеры реально присылают.

## Единственное, что осталось открытым намеренно

- **Round-robin на несколько ключей одного провайдера** (аккаунт мамы и
  т.п.) — делать только если конкретный провайдер (вероятнее всего
  Gemini, дневная квота) реально станет узким местом на практике, не
  превентивно.

## Отложено осознанно (см. GOALS.md → «Не цели»)

- Полный автобенчмаркинг моделей вместо ручной tier-таблицы.
- Многопользовательский/конкурентный доступ к одному инстансу ядра.
- Погоня за паритетом с платными frontier-моделями.

## Как этим пользоваться, если меня (Claude) рядом нет

Каждый пункт — независимый файл или локальная правка, можно брать по
одному сверху вниз. P0 — приоритет всегда, даже если открываешь этот файл
через полгода. Если что-то из P0 уже сделано в коде, но чекбокс не
обновлён — обнови чекбокс, не переделывай задачу заново.
