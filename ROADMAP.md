# Roadmap

Бэклог полировки ядра, по приоритету. P0 — реальные дыры в надёжности,
не украшательства. Ниже — фичи и операционка, по убыванию важности.
См. [GOALS.md](GOALS.md) для контекста "зачем" и принципов, которым
бэклог не должен противоречить.

## P0 — надёжность (делать в первую очередь)

- [ ] **Таймаут на `chat()` в реальных запросах.** Сейчас таймаут
      (12с) есть только у `ping()` внутри health-check. `Router.execute()`
      вызывает `provider.chat()` без ограничения по времени — если
      провайдер не отвечает и не рвёт соединение сам, `AI.generate()`
      зависает навсегда. Нужно: `AbortController` с дефолтным таймаутом
      (например 30-45с, настраиваемым через опцию), передаваемым в
      `options.signal`, который провайдеры уже принимают.
- [ ] **Обрезка истории памяти.** `MemoryManager.buildMessages()` отдаёт
      всю историю сессии без ограничений. Долгий диалог рано или поздно
      превысит context window модели → ошибка вместо ответа. Нужно:
      лимит по числу последних сообщений или грубой оценке токенов
      (симв./4), обрезка с сохранением system-промпта.
- [ ] **Линтер `.env` (`npm run doctor`).** За эту сессию вручную
      найдены: строка `test: curl ...` ломающая парсинг, перепутанные
      местами `CLOUDFLARE_ACCOUNT_ID`/`CLOUDFLARE_API_TOKEN`, реальный
      секрет в закомментированной строке. Это системная проблема, не
      разовая случайность — нужен скрипт, который на старте (или по
      команде) проверяет `.env`: непустые обязательные поля, отсутствие
      случайных не-`KEY=VALUE` строк, нет утечек в комментариях.
- [ ] **Базовые автотесты (`node:test`, без зависимостей).**
      Покрыть: `ModelRegistry` (кулдаун классификация + `eligible()`),
      `Router.rank()` (tier побеждает keyword/latency), `MemoryManager`
      (персистентность переживает новый инстанс). `npm test` в
      `package.json`.

## P1 — архитектурная полировка

- [ ] **`AI.status()`** — программный снимок реестра (alive/cooldown/tier
      по каждой модели) без парсинга консольных логов.
- [ ] **Рандомизация внутри одного tier** при равном score — сейчас
      детерминированный порядок бьёт по дневной квоте одной и той же
      модели вместо распределения нагрузки между эквивалентными по силе.
- [ ] **Файловое логирование** (`utils/logger.js` сейчас только в
      консоль) — актуальнее теперь, раз планируется удалённое управление
      с телефона без доступа к терминалу на ноуте.
- [ ] **JSDoc-типы на публичном API** (`generate/code/roleplay/analyze`,
      конструктор `AIKernel`) — для автодополнения в чужом проекте без
      необходимости лезть в исходники ядра.

## P2 — новые возможности

- [ ] **Streaming-ответы** (`stream: true`) — все провайдеры
      OpenAI-совместимые и это поддерживают, ядро сейчас всегда ждёт
      полный ответ целиком.
- [ ] **Tool-calling passthrough** (`tools`/`tool_choice` в `chat()`) —
      нужно, если когда-то понадобится агент с функциями.
- [ ] **Авто-классификация `task` по содержимому промпта** — сейчас
      обязателен явный параметр `task`.
- [ ] **Round-robin на несколько ключей одного провайдера** (аккаунт
      мамы и т.п.) — делать только если конкретный провайдер (вероятнее
      всего Gemini, дневная квота) реально станет узким местом на
      практике, не превентивно.

## P3 — операционка и безопасность

- [ ] **Pre-commit хук, ловящий похожие на секреты строки** — страховка
      перед пушем в GitHub (запланирован, приватный репозиторий).
- [ ] **Учёт примерного расхода** (`usage.json`: запросы/токены в день
      по провайдеру) — видимость до того, как лимит внезапно кончится.
- [ ] **Оформление под переиспользуемый пакет** (`package.json`
      main/exports) — чтобы «просто закинуть ядро в проект» было
      буквально copy-paste, без разбора структуры.

## Отложено осознанно (см. GOALS.md → «Не цели»)

- Полный автобенчмаркинг моделей вместо ручной tier-таблицы.
- Многопользовательский/конкурентный доступ к одному инстансу ядра.
- Погоня за паритетом с платными frontier-моделями.

## Как этим пользоваться, если меня (Claude) рядом нет

Каждый пункт — независимый файл или локальная правка, можно брать по
одному сверху вниз. P0 — приоритет всегда, даже если открываешь этот файл
через полгода. Если что-то из P0 уже сделано в коде, но чекбокс не
обновлён — обнови чекбокс, не переделывай задачу заново.
