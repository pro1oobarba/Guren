# Changelog

История изменений ядра поверх исходного MVP (3 провайдера, README.md/
00-STRUCTURE.md как их писал первый автор). Формат: что изменилось и почему —
не просто "что", а мотивация, чтобы не переоткрывать те же вопросы заново.

## 2026-08-06 — responseFormat/maxTokens passthrough (первая внешняя интеграция)

Первый реальный внешний потребитель ядра — `ai-dungeon-master`
(`C:/Users/Turni/ai-dungeon-master`, подключён как `file:`-зависимость).
Заменял свою мини-цепочку на 3 провайдера на `AI.roleplay()` и сразу
уткнулся в два недостающих параметра.

### `responseFormat` passthrough
`BaseProvider._openAIChat` получил `options.responseFormat` →
`body.response_format`, по образцу уже существующего `tools`/`toolChoice`.
`Router.execute()` и `kernel.js generate()` пробрасывают его насквозь.
Нужен внешнему коду для честного JSON-режима у моделей, которые его
поддерживают (весь OpenAI-совместимый слой — 8 из 9 провайдеров).
Cloudflare (свой формат запроса, не через `_openAIChat`) тихо игнорирует
поле — не ломается, просто не участвует.

### `maxTokens` passthrough
Тем же путём — `options.maxTokens` уже принимался `_openAIChat` (дефолт
1024), но `Router.execute()`/`kernel.js generate()` не давали внешнему
коду его переопределить. Всплыло на практике: reasoning-модели (например
`gemini/models/gemma-4-26b-a4b-it`) пишут рассуждение прямо в `content`
через `<thought>...</thought>` (не в отдельное поле, как `o1`/`DeepSeek-R1`
с их `reasoning_content`) — на дефолтных 1024 токенах модель обрывается
посреди рассуждения, ответ никогда не доходит до финального JSON.
`ai-dungeon-master` теперь запрашивает `maxTokens: 2048` для DM-ответов —
доля успешных (не local-fallback) ходов выросла заметно на practice-тесте.

**Не до конца решено**: даже 2048 токенов не гарантия — модель может
рассуждать ещё дольше. Ядро не умеет отличать "этот кандидат системно не
укладывается в responseFormat" от обычной ошибки — такие модели не
уходят в кулдаун и будут выбираться роутером снова. Кандидат на будущее
улучшение: если вызывающий код передаёт `responseFormat` и получает
ответ без `[DONE]`-подобного естественного конца (или контент не похож
на JSON), можно эвристически понижать такого кандидата в ранге — не
делали, потому что это app-level знание ("это должен был быть JSON"),
а не то, что видит `Router` сейчас.

Тесты: 2 новых в `test/router.test.js` (`execute() пробрасывает
responseFormat`, `execute() пробрасывает maxTokens`) — оба по образцу
существующего теста на `tools`/`toolChoice`. 32/32 зелёных.

## 2026-08-05 (ночь, продолжение 3) — P3 из ROADMAP.md: последний блок

### Pre-commit хук против утечки секретов
`scripts/checkSecrets.js` сканирует staged файлы (`git diff --cached`)
на известные форматы ключей, с которыми этот проект уже сталкивался
(Groq `gsk_`, OpenRouter `sk-or-v1-`, Cerebras `csk-`, Cloudflare
`cfut_`, HuggingFace `hf_`, GitHub `github_pat_`, `sk_live_`-стиль) плюс
жёсткое правило: `.env` в staged — всегда блокировка, вне зависимости
от содержимого. Не универсальный secret-scanner — точечная защита от
повторения конкретных утечек, что уже случались за эту сессию.

`.git/hooks/` не версионируется git-ом, поэтому сам хук лежит в
`scripts/` (виден в истории репозитория), а `npm run hooks:install`
(`scripts/installHooks.js`) один раз ставит тонкую обёртку в
`.git/hooks/pre-commit`. Проверено: коммит с поддельным `gsk_...`
в тестовом файле заблокирован с понятным сообщением; чистый коммит
проходит без задержек.

### Учёт примерного расхода
`utils/usageTracker.js` — `usage.json`, синхронная запись как у
`MemoryManager`, группировка по дню/провайдеру/модели: `requests`,
`promptTokens`, `completionTokens`. `BaseProvider._openAIChat()` теперь
парсит `data.usage` из ответа (`prompt_tokens`/`completion_tokens`) и
отдаёт его наверх; `Router.execute()` пробрасывает `usage` в
`GenerateResult`; `kernel.js.generate()` пишет в трекер после каждого
успешного ответа. `AI.usageToday()` — быстрый доступ без похода в файл
руками. В стриме usage не собирается (не все провайдеры отдают его без
`stream_options.include_usage`, а тянуть эту зависимость ради
необязательной статистики избыточно) — считается только `requests`.

### Оформление под переиспользуемый пакет
`package.json`: `main` теперь указывает на `kernel.js` (реальный
библиотечный фасад), а не на `index.js` (это CLI-демка, остаётся
доступной через `npm start`). Добавлен `exports: { ".": "./kernel.js" }`
для явности при `import`. Описание пакета переписано без жёсткой
привязки к числу провайдеров (раньше было "между Groq, OpenRouter и
Cloudflare" — устарело бы при следующем добавлении/удалении провайдера,
как и было с самим README на старте этой сессии).

## 2026-08-05 (ночь, продолжение 2) — P2 из ROADMAP.md: streaming

### Streaming-ответы
`BaseProvider._openAIChatStream()` — ручной разбор SSE (`data: {...}\n\n`,
`data: [DONE]`) без зависимостей: `ReadableStream.getReader()` +
`TextDecoder`, построчный парсинг с буфером для неполных строк между
чтениями (частый источник багов в самодельных SSE-парсерах — не
забыл). На каждый `delta.content` дёргается `options.onToken(delta)`,
в конце возвращается `{ content, toolCalls: null }` с полным склеенным
текстом. Все 8 OpenAI-совместимых провайдеров получили ветвление в
`chat()`: `options.stream ? _openAIChatStream(args) : _openAIChat(args)`.
Cloudflare не поддержан — свой формат ответа, не OpenAI-совместимый (как
и `tools` там же не поддержаны).

**Осознанное упрощение**: во время стрима tool_calls не собираются
(сборка потоковых дельт аргументов функции — отдельная нетривиальная
задача, а одновременная потребность в tools и стриме в одном запросе —
редкий кейс). Если нужны оба — обычный (не потоковый) вызов.

**Обрыв потока и fallback — сознательное решение, не очевидное**: если
соединение рвётся ДО первого токена, это обычная ошибка — `Router`
делает fallback на следующую модель, как обычно. Но если рвётся ПОСЛЕ
того, как хотя бы один токен уже ушёл в `onToken` (то есть вызывающий
код уже что-то показал пользователю), молча переключаться на другую
модель означало бы либо задвоить текст, либо незаметно оборвать ответ
без объяснения. Вместо этого `_openAIChatStream` бросает ошибку с полем
`partialContent`, `Router.execute()` не делает fallback и не помечает
модель мёртвой (частичный успех — не однозначный признак поломки),
`kernel.js.generate()` сохраняет частичный ответ в память сессии перед
тем, как пробросить ошибку выше — история диалога не теряет уже
случившийся (хоть и оборванный) ход ассистента.

Проверено: 4 теста на мокнутом `fetch`+`ReadableStream` (сборка дельт,
устойчивость к битому JSON-куску между чтениями, оба случая обрыва) плюс
реальный стрим по сети через Groq (9 чанков, склеенный текст совпал с
`result.text`).

## 2026-08-05 (ночь, продолжение) — P2 из ROADMAP.md: auto-task + tool-calling

### Авто-классификация `task` по промпту
`router/classifyTask.js` — эвристика по регуляркам: код-блок/`function`/
`import`/traceback → `code`, "ты — персонаж"/ролплей-слова → `roleplay`,
"сравни"/"объясни почему"/"разбери" → `analysis`, иначе `general`.
`kernel.js.generate()` использует её, только если `task` не передан явно
(явный `task`, включая явное `'general'`, всегда в приоритете).

**Пойманный тестами баг при разработке**: `\b` (word boundary) в
JS-регулярках без флага `/u` не видит кириллицу как "словесный" символ —
`/сравни\b/` тихо не матчился вообще, промпт "Сравни Python и
JavaScript" классифицировался как `general`. `npm test` поймал это сразу
(один из шести новых тестов на `classifyTask` упал), не пришлось искать
руками. Убрал `\b` вокруг всех кириллических слов в паттернах.

### Tool-calling passthrough + рефакторинг провайдеров
`generate({ tools, toolChoice })` пробрасывается до
`chat/completions` как есть (формат OpenAI tools API), `toolCalls` из
ответа модели возвращается в `GenerateResult`. Контракт `provider.chat()`
поменялся: раньше возвращал голую строку, теперь
`{ content, toolCalls }` — на всех провайдерах, включая Cloudflare
(`toolCalls: null`, Workers AI формат его не поддерживает).

Заодно рефакторинг: добавлен `BaseProvider._openAIChat()` — общая
реализация `fetch` + сборка `body` + парсинг ответа для всех
OpenAI-совместимых провайдеров (Groq, OpenRouter, Cerebras, SambaNova,
DeepInfra, Hyperbolic, Gemini, HuggingFace — 8 из 9). Раньше один и тот
же код был скопирован в каждый файл; теперь добавить новую опцию
(как tools/toolChoice) — правка в одном месте, а не в восьми файлах.
Cloudflare не участвует (свой формат запроса/ответа), GitHub-заглушка
не участвует (всегда `enabled: false`, до `chat()` дело не доходит).

Проверено сквозным вызовом с реальным инструментом (`get_weather`) на
Cerebras — модель корректно вернула `tool_calls` с аргументами.

## 2026-08-05 (ночь) — P1 из ROADMAP.md

### `AI.status()`
Метод в `kernel.js`, возвращает снимок `ModelRegistry` в удобном виде:
`{ provider, modelId, tier, state, latency, error, cooldownRemainingMs }`,
где `state` — `alive | cooldown | retryable`. Раньше состояние моделей
можно было увидеть только через консольные логи `HealthChecker` или
сырой `registry.toJSON()` без tier/cooldown-контекста.

### Рандомизация внутри tier
`Router.rank()` добавляет небольшой случайный джиттер (0-5, сопоставимо
с `latencyScore`/`aliveBonus`, на порядки меньше веса tier) к score
каждого кандидата. Раньше при двух моделях одного tier с похожей
задержкой ранг был жёстко детерминирован — весь трафик уходил в одного
и того же кандидата, съедая его дневную квоту в одиночку, пока
равноценная модель простаивала. `Router` принимает `random` в
конструкторе (по умолчанию `Math.random`) — инъекция для
детерминированных тестов. Джиттер попутно вскрыл скрытую нестабильность
в тесте на fallback (`execute()` мог ни разу не тронуть "плохую" модель,
если джиттер её не выбирал первой) — тест переписан с `random: () => 0`.

### Файловое логирование
`utils/logger.js`: опциональный `LOG_FILE=./kernel.log` в `.env`.
Дублирует каждый лог в файл без ANSI-кодов, с полным ISO-таймстампом
(в отличие от короткого `HH:MM:SS` в консоли — файл может жить дольше
одного дня). Без `LOG_FILE` поведение не меняется. Мотивация — план на
управление ядром удалённо с телефона, где консоли перед глазами не будет.

### JSDoc-типы на публичном API
`kernel.js` получил `@typedef` на `GenerateArgs`, `GenerateResult`,
`ModelStatus`, `TaskType`, `ModelState` и JSDoc-аннотации на
`generate/code/roleplay/analyze/status`. Даёт автодополнение в IDE
чужого проекта без необходимости лезть в исходники ядра — без перехода
на TypeScript и без новых зависимостей.

## 2026-08-05 (вечер) — P0 из ROADMAP.md

### Таймаут на реальные запросы
`Router.execute()` раньше вызывал `provider.chat()` без ограничения по
времени — только `HealthChecker.ping()` имел таймаут. Завис провайдер
без честного разрыва соединения → `AI.generate()` висел бы бесконечно.
Добавлен `AbortController` с дефолтом 45с (`DEFAULT_TIMEOUT_MS`),
настраиваемый через `AI.generate({ timeoutMs })`. При срабатывании
таймаут классифицируется как обычная ошибка модели — кандидат уходит в
кулдаун, роутер пробует следующего по рангу.

### Обрезка истории памяти
`MemoryManager` получил два независимых лимита: `maxStoredMessages`
(по умолчанию 60 — что хранится в `memory-store.json`, защита от
бесконечного роста файла) и `maxContextChars` (по умолчанию 24 000 ≈
6000 токенов — что реально уходит в запрос модели, обрезается с конца
истории, всегда хотя бы одно последнее сообщение). Раньше вся история
сессии без ограничений шла в `buildMessages()` — долгий диалог рано или
поздно превысил бы context window скромной free-tier модели.

### `npm run doctor` — статический линтер `.env`
`scripts/checkEnv.js` разбирает `.env` построчно (не через
`process.env`, чтобы ловить секреты, забытые в закомментированных
строках). Проверено на всех трёх реальных багах, найденных вручную за
сессию — линтер ловит их все:
- строка не в формате `KEY=VALUE` (случай с вставленной `curl`-командой);
- живой секрет внутри `#`-комментария (случай с GitHub PAT);
- `CLOUDFLARE_ACCOUNT_ID`, не похожий на 32-символьный hex (случай с
  перепутанными местами Account ID и API Token).

Плюс: пустые обязательные ключи, дублирующиеся ключи, лишние пробелы
вокруг значения.

### Автотесты
`npm test` (`node --test`, без внешних зависимостей) — 14 тестов в
`test/`: кулдаун-классификация и `eligible()` в `ModelRegistry`,
приоритет tier над latency/keyword и fallback-логика в `Router`,
персистентность и оба лимита обрезки в `MemoryManager`.

### Роутинг: tier вместо угадывания по ключевым словам
Добавлен `router/modelTiers.js` — курируемая вручную таблица "весовой
категории" модели по семейству (DeepSeek-V3/R1, Llama-70B, GPT-OSS-120B →
tier 3; средние — tier 2; edge-модели ≤8B → tier 1). `Router.rank()`
переписан: раньше latency и совпадение по ключевому слову в id могли
перевесить реальную силу модели (мелкая 8B с удачным словом в названии
обходила 70B). Теперь tier — главный сигнал, keyword/strengths и latency
решают только внутри одного tier.

**Почему не автоматический бенчмарк вместо ручной таблицы**: каталоги
бесплатных моделей (особенно OpenRouter) меняются каждую неделю — любой
автопрогон устареет за 7 дней. Судьёй пришлось бы ставить одну из тех же
бесплатных моделей — шум и предвзятость в оценке. Публичные бенчмарки
этих модельных семейств уже существуют и не скачут неделя от недели.
Автобенчмарк также сжигал бы дефицитную дневную квоту Gemini/HuggingFace
без реального выигрыша в точности.

### ModelRegistry: "остывание" вместо вечной смерти
Раньше модель, помеченная мёртвой при health-check на старте, оставалась
мёртвой до следующего ручного перезапуска процесса — даже если ошибка
была временной (rate limit) или дневная квота уже сбросилась.

Добавлено поле `retryAfter` и метод `eligible()` (живые + остывшие
мёртвые). `Router.rank()` теперь использует `eligible()` вместо
`alive()` — остывшая модель попадает в кандидаты, реальный вызов в
`execute()` либо оживляет её обратно, либо продлевает кулдаун.

Кулдаун классифицируется по тексту ошибки:
- **6 часов** — дневная квота (RPD) или пустой баланс (`payment
  required`, `insufficient funds`, `depleted... credits` и т.п.) — само
  не пройдёт до завтра/пополнения.
- **10 минут** — rate limit (429/402/"quota", без явного признака
  дневного лимита) — обычно снимается за минуты.
- **2 минуты** — прочие ошибки (сеть, таймаут) — возможно, разовый сбой.

### Память: персистентность
`MemoryManager` переписан на синхронное чтение/запись JSON-файла
(`memory-store.json`, в `.gitignore`) вместо `Map` в оперативной
памяти. Публичный API не изменился (`get/append/buildMessages/clear`) —
остальной код ничего не знает о персистентности. Проверено: сообщение,
отправленное в одном процессе, вспоминается в новом процессе после
полного рестарта.

### Git
`git init` + первый коммит. Проверено `git status` перед стейджингом —
`.env`, `health-report.json`, `memory-store.json`,
`.claude/settings.local.json` не попадают в индекс.

### Открытые вопросы / не сделано
- Учёт дневной квоты сделан реактивно (через классификацию ошибок в
  cooldown), не проактивно (нет счётчика "сколько запросов уже
  потрачено сегодня по каждой модели"). Проактивный счётчик потребовал
  бы хардкодить RPD-лимиты по провайдеру/модели — хрупко при смене
  каталогов, решили не делать, пока реактивного кулдауна достаточно.
- Второй набор ключей (второй Google-аккаунт и т.д.) для увеличения
  дневного бюджета — не реализовано, роутер сейчас держит один
  экземпляр провайдера на один ключ. Делать только если конкретный
  провайдер (вероятнее всего Gemini) реально станет бутылочным горлышком.
